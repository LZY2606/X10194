# 构建指纹舱（Build Fingerprint Vault）

离线复盘远程构建缓存 key 的来历：导入不可变的构建动作清单，派生出规范化指纹与解释，
展开 key 的每个组成部分，比较两次动作为何命中/未命中，并对“同键异输出”做争议仲裁、
对“摘要事后纠正”做只沿可达子图的失信传播。不连接任何真实缓存服务。

## 运行

```bash
npm install
npm test -- --run
npm run dev -- --host 127.0.0.1 --port 5254 --strictPort
# 打开 http://127.0.0.1:5254
```

技术栈：TypeScript + Node.js（内置 `node:sqlite`，无原生编译）+ Vite 6（dev 中间件直连 SQLite）+ React 18 + Vitest。

## 页面

- 动作 DAG：分层渲染依赖，区分成功/失败/阻塞/失信/图无效，点击节点展开指纹。
- 指纹展开：command、args、env、toolchain、platform、inputs、deps 七个组件的原始值、
  规范化值、解释与喂哈希的明确字节（hex），并展示依赖结果钉住与未声明环境告警。
- 命中比较：逐组件对照两个动作，给出首个分叉组件与 true-hit / disputed-hit / miss 判定。
- 争议条目：同键异输出时双方来源与结果 hash 都保留，按首次观察顺序记录，绝不最后写入覆盖；
  可继续追加观察，条目只追加不覆盖。
- 规则版本：草案 JSON 编辑、对全部历史动作干跑（新增合并、同键分组、危险碰撞反例）、
  批准形成不可变新版本并在其 key 命名空间重放、回滚生成“恢复版”而非改写历史。
- 失信传播 / 导入恢复：纠正某输入摘要，仅使反向可达动作失信（共享子图精确传播）；
  支持乱序（前向引用）导入、提交前模拟崩溃与重启后回滚 pending 批次的审计日志。

## 关键设计

- 规范化只处理规则中显式声明为等价的部分：路径分隔符归一、路径前缀别名、
  声明的可交换参数标志（相邻 `(flag,value)` 单元排序，其余参数严格保序，不做全局排序）、
  symlink 按链接字符串或目标内容摘要、忽略权限位、忽略平台。
- 动作 key 钉住每个依赖的 `dep key + 结果版本 hash + 成败`；失败节点不产生缓存条目，
  其下游标记为 blocked。
- 所有哈希输入经 `ByteWriter` 长度前缀编码（UTF-8、hex 摘要转原始字节、小端 varint、
  组件带语义 tag），杜绝拼接歧义；key 为 SHA-256。
- 原始清单以 `raw_json` 原样保存，规范化键、组件解释、纠正在独立派生/纠正表中。
- SQLite 启用 WAL；整批导入在 SAVEPOINT 内提交，崩溃后重启自动回滚 pending 导入并留痕。

## 测试（33 项）

覆盖路径 separator、symlink 两种取证策略、环境缺失与未声明环境、依赖共享与失败钉版本、
摘要纠正的精确传播、同键异输出争议、规则干跑/批准/回滚、乱序导入、崩溃后 WAL 恢复，
以及字节编码的无歧义性。
